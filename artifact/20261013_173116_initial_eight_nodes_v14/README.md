# v14 执行与复现约定

本版从原始TXT/XLSX重建全部八节点事实；模型只接受该节点截止的证据包。主线与阶段边界在代码 prepare_analysis.py 中公开冻结，全部合格候选仍参与模型比较。此前分析正文不作为模型输入。v14只在有原始反例时改事实；目前八节点202条当日事实与v13相同。

生成分析：固定 analysis_prompt.txt、runtime_config.json、JSON schema、原始输入与官方固定历史资料。使用 Codex CLI 0.162.0-alpha.17.2、gpt-6.1-sol、high reasoning，ephemeral 新进程，忽略用户配置和规则。CLI未提供本流程可用的固定seed或temperature；不承诺未来字节相同。每个节点保存真实命令、提示词、响应、token用量及哈希。密钥与登录信息不打包。

两种入口的含义必须区分：

- fresh：新目录从原始输入重建事实，再真实调用Codex重新生成分析，生成全部48文件。检查事实、主线、阶段、结论及外部资料资格的一致性；允许行文变化。
- frozen：新目录从原始输入重建事实，只有台账哈希与已审阅分析绑定一致才回放该分析。规范化OOXML包元数据与等价关系ID，核对48文件和ZIP哈希完全一致。此模式不称重新推理。

所有最终正式文件须经历八份Word全文渲染、八份Excel全填充范围渲染、32图检查、修复、独立解包重开。原始输入、代码、资料与审计留在工程包；比赛ZIP仅八日期目录、48文件。平台评分未取得时不预报提分。保留一次改进和一次复现提交机会，平台上传由用户执行。
