# 同一提示词两轮 GPT 执行 trace 复核

复核日期：2026-10-09。比较 GPT 独立重做 v2 与本轮 independent v4。评测指标来自用户反馈，未取得平台提交 ID、逐节点扣分或评测程序内部 trace。

## 查到了什么

用户任务提示逐字一致，记录中的模型与推理档位也一致；原始数据没有变化。两轮却独立生成了不同程序，并采用了不同的事实纳入口径、自建标签和主线选择。能直接确认的是这些执行差异，不能仅用“随机波动”解释，更不能把本次增量归给提示词优化。

| 项目 | GPT v2 | 本轮 v4 | 证据 |
|---|---|---|---|
| 任务提示 | 1085 字符，SHA256 `ec4622393f87d2067ec960df169dab9f7354d1173ab5138e0f73b2e2b0b7eeef` | 完全相同 | 两 trace 第 12 行；prompt_comparison.json |
| 模型标识／推理档位 | gpt-6.1-sol / high | gpt-6.1-sol / high | 两 trace 第 8 行及生成期间 turn_context |

| 首次生成任务时长 | 57.77 分钟 | 50.56 分钟 | task_complete.duration_ms，排除后续评测讨论 |
| exec 包装调用 | 81 | 74 | 只数 response_item，不能等同于嵌套工具实际调用数 |

| API usage.output_tokens 累计 | 112531 | 91685 | 每 response_id 去重；不把累计输入当作独立阅读量 |

本轮时间和输出量都更少，因此没有证据说“本轮因投入更多而提高”。两轮基础指令哈希相同，但开发者指令块及仓库读取上下文并非完全冻结：v4 第 22 行读取 README，第 25 行工具返回已经含 v2 总分 69.0354；v2 对应第 26 行返回没有该成绩。这里只证明读取背景不同，不证明这个成绩影响了具体代码选择。模型后端精确快照、temperature、模型采样 seed 未从现有记录取得。

按同一原始日期与雷达批号定位，两轮共保留 172 个纳入事件，v4 移除 40 个、新增 3 个：`212 - 40 + 3 = 175`。此键仅用于审计同一原始记录，不是事件生成时的关联依据。v2 将部分批次拆成轨迹分支，所以雷达候选总数 433 与 427 也不是同一统计粒度。

40 个移除事件按程序排除机制分为下列互斥类别；这些是“为什么程序排除”的计数，不是“官方证明排除正确”的计数。

| 排除机制 | 数量 | 可追溯实现差异 |
|---|---:|---|
| 实名舰艇缺显式数量 | 17 | v2 对单一实名舰艇允许语义数量 1；v4 只解析显式“数字＋艘” |
| 无时段文本的同型同日歧义 | 12 | v4 将具体区域与兼容的大海域都计为区域支持，缺时段时可能同分；随后禁止歧义文本桥接 |
| 多分支雷达整批否决 | 6 | v2 按起始坐标拆分并允许两文本限定分支；v4 保留整批并以并行异地观测否决 |
| 单源任务整体排除 | 2 | v2 保留活动并填“任务未核实”；v4 任务不足两类来源即否决事件 |
| 具体区域与轨迹容差冲突 | 2 | v2 宽海域包络与 v4 具体区域中心距离规则不同；不能以工程容差代替精确地理真值 |
| 关联文本任务冲突 | 1 | v2 只从通过兼容检查的文本组选择；v4 先分配同事件候选，再保留明确任务冲突 |

另有 55 个共同纳入事件的区域字段变化，全部为飞机；在本次比较的主体、数量、任务、活动时段中没有其他变化。v2 从包含关系输出“东海／南海／黄海”，v4 输出兼容的更具体区域。比如 5.10 歼-15D，军情009写钓鱼岛，舆论027写东海；v2 输出东海，v4 输出钓鱼岛海域。具体区域可提高与细区答案的吻合程度，但宽海域文本本身不是对细区的独立确认，v4 的粗粒度距离规则也不能证明精确边界。不能把 55 次细化全部称为准确性修复。

## 原始证据定向复核

原始 TXT 全文、SHA256、重新读取的 Excel 行保存于 raw_review_examples.json。这里人工复核了 7 个定向案例，不是无偏样本；判断依据来自原始资料，不以任一实现输出作为真值。

1. **7.9 山东号，SHIP-AF41F705A929BC：本轮存在过严排除。** 军情002、舆论015均明确同一艘实名舰艇、东海中部、14:28—16:53、例行部署；舰船第2、8、37、58等13行同样一致，数量均为1。没有证据显示编队中多艘同名船。v4 唯一排除理由是两个文本没有显式“1艘”。当前复核判断：可以把单一实名舰体的语义数量与泛称舰级数量区别处理，限定活动已唯一关联后纳入；不能给所有机型、舰级默认1。这个是事实语义口径选择，尚无官方该事件扣分确认。
2. **5.18 E-737，AIR-1CC2A2CC80B4D1：真实存在雷达冲突，分支处置不同。** 军情010北康暗沙、舆论005南海14:55—16:20；飞机第85与275行同在14:55，位置分别约123.10E/35.22N与112.40E/5.53N，后续也为两组持续记录。v2 纳入文本限定的南海分支，v4 整批排除。原始证据不能证明另一持续分支只是噪声，所以当前严格规则下排除有依据；若允许独立分支，应另保留分支身份不确定性。不能取中位数或按行数消除冲突。
3. **6.17 075早段，SHIP-37F0DC0E1C2114：评分区分度不足会造成歧义扩大。** 军情041写连云港05:56—07:21，舆论001明确一艘075在连云港，舰船第2、31、92等10行同一地区和时段。晚段另有军情035黄海20:20—22:45与舆论004泛黄海。v4 对舆论001关联具体连云港和泛黄海都加相同区域分，随后判同分歧义。现有材料仍没有舆论001的明确时间，不能仅据文本唯一顺序强行匹配；但不能把“程序区分不了”直接宣称为“原始证据一定不可区分”。下一步应联合全部时段与具体区域约束检验。
4. **5.10 RC-135，AIR-9D6E262963D302：未知字段与活动纳入绑定不同。** 军情008支持美国两架RC-135在东海活动，舆论022支持08:14—10:39侦巡类活动，飞机第16、66、111等11行一致。具体“电子侦察”任务只在雷达或平台用途中出现，不应肯定为已双源核实任务。v2 任务标未知，v4 排除整起活动；这是任务作为整起纳入必要条件的不同解释，不是明确文本冲突。
5. **6.9 轰-6K，AIR-8C086A90C01249：确实改变了关联文本。** v2 军情026是无时段长江口外海；v4 军情032是无时段东海南部远程轰炸训练。舆论028与飞机第61、78、106等10行支持11:15—13:40战备警巡，轨迹约123.5—123.7E/26N。v2 宽包络允许026并忽略不可兼容的032，v4 选择032后保留任务冲突并排除。关联032仍是候选假设，不可因匹配分高就把“远程轰炸训练”当真；本次仅确认原版存在另一活动文本误配风险，没有官方真值判断。
6. **5.10 815A，SHIP-A429047D9CB3EB：新增有明确依据。** 军情033温州20:20—22:45例行部署，舆论036东海一艘815A例行部署，舰船第42、43、60等13行温州、1艘、相同时段任务。v2 将平台名称“电子侦察船”中的“电子侦察”误抽为任务候选，使正确组不能通过；v4 区分平台用途词与实际任务后纳入。这里没有依赖文件编号相等。
7. **5.10 歼-15D，AIR-026EC345AA8CFC：区域粒度变化不等于重新关联。** 两轮采用军情009和舆论027，飞机第13、23、67等11行一致。军情具体钓鱼岛、舆论泛东海。区域从东海变为钓鱼岛海域，说明细区支持规则改变；不能说三源都明确报出钓鱼岛。

## 自建“真值”也发生变化

在可以按日期／雷达批号定位、且两边明确测试事件纳入的16对标签中，4对期望不同：v2 H01 / v4 G28（E-737）、H07 / G29（AW-159）、H12 / G44（山东号）、H13 / G31（无侦-7）。其中E-737、AW-159、无侦-7三个多轨迹案例的严格整批排除与允许独立分支两种处理不同；山东号则是实名数量语义不同。完整依据见 case_label_comparison.json，不能把16对解释成全部案例的同构对照。

因此，两轮42/42与46/46只表示各自满足自建标准。标签都出自原始材料判读，仍可能存在口径漂移；程序与人工标准同时变化时，全部通过也无法独立确认哪一轮正确。后续对照应先冻结同一份标签、明确“关联正确”“活动可纳入”“字段可肯定”的不同答案，再让两个实现接受相同检查。不会为使本轮通过而改动原标签，本次仅新增审计。

8个节点中6个主线平台改变。v2 历史证据日期平均15.5个，本轮4.625个；v2 主要按日期数排序，并对边界打分后取2或3阶段，较弱变化也可能被分段。本轮 trace 第526行明确报告发现均匀B-52记录被按中点拆分，第518行工具调用已修改为具体区域、任务、间隔划分，均匀序列不再强行分阶段。每节点实际主线与阶段见 trend_comparison.json。

## 复现审计与文件范围

仓库根目录执行：

```powershell
python -X utf8 artifact/20261009_gpt_independent_v4/audit/post_evaluation_trace/inspect_traces.py
```

本脚本只读取两个明确指定的GPT会话、两个GPT版本及原始数据，不读取Claude代码或产物。不导出推理正文、压缩摘要或凭据；记录可见评论、工具代码、用户任务及配置元数据。原始会话文件没有复制到仓库，首任务前缀哈希和行号可用于定位。首任务截止点固定，后续本聊天读取trace不会把统计自我放大。
