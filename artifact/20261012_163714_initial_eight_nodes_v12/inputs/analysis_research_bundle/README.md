# 比赛分析增强资料包

编制日期：2026-10-10。范围：历史公开资料、研究写作和引用审计。

## 建议结论

把“外部资料库 + 少量专家示例 + 固定分析流程”组合使用，不要把范例和Skill当成互相替代的两种模型。优先冻结准确性较好的事实层，只让增强模块生成第二节分析与独立审计记录。

本包中的代码是来源时间与引用资格检查器，不是军事情报处理系统：不读取雷达表、不融合或重建具体部队轨迹、不推断后续部署、不提供行动规划。

## 本轮核对到的限制

用户提供的5份MD规定：节点后信息不可用；日报必须区分事实和推断；第二节主线至少覆盖3个不同日期并概括为2—3阶段；三类比赛内来源的关联与冲突处理不能被外部文章代替。依据分别为01文件“关键限制”、02文件“三源核验原则”、03文件“节点日报规则”、04文件“DOCX内容”。

“无外部资料时分析分原则不超过60”来自用户陈述，本轮在上传5份MD、样例说明和公开可读的赛题页面中没有找到可核对的完整原文。把它记录为待确认的评测口径，不据此保证引用外部资料即可提分。公开比赛页：https://www.heywhale.com/home/competition/6aba1c4f6e5beff2fca33b42 。

压缩包包含10月1—20日的演示输入、10月20日示例日报/明细/4图，不是5—7月初赛原始数据。示例中的事实未被本轮重新完整判定。正式报告应由程序生成，不将人工示范作为正式结果直接提交。

另有一处格式口径差异：04文件允许ZIP含日报/外层目录，压缩包内提交格式说明要求ZIP根目录直接包含日期目录。这里仅记录冲突，不替组织方选择规则；应按平台最新明确要求确定。

## 文件说明

- source_catalog.md / source_catalog.json：10项原始发布页、报告或数据入口，区分专家报告、统计材料、政策材料和方法文件；含发布日期、适用边界、访问核查状态。
- external_data_cards.json：少量逐条定位的公开汇总数值，属于本包人工整理的摘录，不是原发布方的完整原始数据库。
- analysis_example.md / analysis_example.docx：基于10月20日样例第二节的自写示范；没有冒充三源已核实事实。
- generation_prompt.md：可以直接放进现有调用链的分析提示词。
- skill.zip：单一Skill包，含通用来源审计脚本、格式规则、资料目录和写作模板。
- evaluation_plan.md：控制变量实验与未运行项目说明。
- sample_intake_audit.json：样例包清点、原文段落与文件哈希。

## 外部资料怎么变成有用的分析

先写“本段要回答什么问题”，再决定引用什么。历史统计解决基线问题；政策原文提供归属清楚的公开立场；专家案例提供组织方法；方法手册帮助控制假设和不确定性。只多写一句年度宏观背景，并不自动增加分析价值。

一条有用的引用应能补足比较基线、提出合理替代解释、约束结论，或提供相关政策背景。外部材料不能把三源核验未通过的事件变成已核实事件。不要把转载当成独立来源，也不要把模型记忆算作找到的外部资料。

SIPRI当前数据库已在2026年更新，历史年份也可能修订。分析2025节点应优先用已核对的2025年3—4月固定版报告，而不是从2026版Excel筛出2024年行。抓取时间晚于节点本身不必然构成穿越，关键是所使用的内容和版本是否在节点前已公开。

## 使用顺序

先打开source_catalog.md选与主线直接相关的1—3条材料；再读analysis_example.md看写法；接入generation_prompt.md；最后用skill.zip中的来源审计脚本检查时间与引用。不要把整个资料目录无差别塞入每份日报。

Skill及脚本已经进行本地结构和功能测试，测试记录见包内audit/。尚未对初赛8个节点运行生成实验，也未调用比赛平台测评。目录中主体内容可读不等于每个附件都成功下载：未打开的PDF、语言版本日期未核实之处已逐项标明。
