# 赛题 Workflow 全流程与各模块选型

结论：此前列出的 12 个模块覆盖了主要能力，但**不足以直接照着实现完整 Workflow**。缺少数据盘点、时间隔离、原始记录去重、雷达轨迹拆分、候选事件全局分配、逐字段证据、重点主线选择、生成后事实核对、失败恢复和实验评测等步骤。下面按真实执行顺序补齐。

## 0. 总体运行方式

```text
配置节点与时间边界
  → 盘点文件 → 解析/清洗 → 雷达轨迹整理与异常标记
  → 文本抽取 → 名称归一 → 跨源候选召回 → 事件归并/去重
  → 逐字段证据与冲突核验 → 可信事件准入
  → 海域判定与当日统计 ──────────────┐
  → 跨日追踪与重点主线选择 ────────┤
                                 ↓
                    写正文 / 生成明细表 / 绘图
                                 ↓
                     事实复核 → 格式验收 → 归档
```

程序负责规定顺序、保存中间结果和执行硬约束。每个模块可选规则、模型或受限 Agent；模型结论必须带证据，不能直接绕过准入规则。

## 1. 数据准备：把原始材料变成可追溯记录

| 步骤：输入 → 输出 | 可选方案 | 推荐与检查点 |
|---|---|---|
| **1. 节点配置与时间隔离**：赛段、节点 → 允许读取的日期集合 | A. 配置文件列出节点；B. 数据目录自动发现并按赛段过滤 | **A+B**。每次运行固定 `stage/start/node`；节点之后的文件在读取前就排除，避免泄漏。 |
| **2. 文件盘点**：目录 → 文件清单 | A. 按日期/来源扫描；B. 加文件哈希和缺失报告 | **B**。记录路径、来源、日期、大小、哈希；检查每天两类 TXT 和雷达工作簿是否齐全。 |
| **3. 格式解析**：TXT/XLSX → 原始记录 | A. 正则与 `openpyxl`；B. 解析失败的文本交给 LLM 修复 | **A 主、B 兜底**。保留文件名、工作表、行号、原文片段；解析失败不能静默跳过。 |
| **4. 清洗与去重**：原始记录 → 清洁记录 | A. 编码、空值、时间格式和精确重复处理；B. 相似文本去重 | **A+B**。重复报道仍保留各自来源；同来源复制稿不能冒充两类独立证据。 |
| **5. 雷达轨迹组装**：雷达行 → 平台轨迹 | A. 按批号聚合；B. 按批号再用时空连续性拆分/合并；C. 轨迹聚类模型 | **B**。一行通常是一个轨迹点，不是一次事件；同批号若发生明显跳变，要保留拆分原因。 |
| **6. 雷达异常检测**：轨迹 → 异常标签 | A. 经纬度、时间、速度、数量、区域规则；B. 时序异常检测模型；C. LLM 解释疑点 | **A+B 可选**。异常先标记并降权/隔离，结合文本判断；雷达不具有绝对优先权。 |

## 2. 知识整理：得到有来源的候选事件

| 步骤：输入 → 输出 | 可选方案 | 推荐与检查点 |
|---|---|---|
| **7. 文本要素抽取**：文章 → 主体、平台、数量、时间、区域、任务、动作 | A. 词典/正则；B. LLM 按 JSON Schema 抽取；C. 微调抽取模型 | **A+B**。每个字段记录原文定位；“报道时间”和“活动时间”必须分开。 |
| **8. 名称与单位归一**：抽取字段 → 标准字段 | A. 国家/平台/区域别名表；B. 向量检索或 LLM 消歧；C. 实体知识图谱 | **A 主、B 处理歧义**。保留原值和标准值；主体—平台错配要标记。 |
| **9. 跨源候选召回**：文本记录与轨迹 → 候选配对 | A. 日期、主体、平台、时间窗和海域筛选；B. 向量检索；C. 混合检索加重排序 | **C**。先尽量找全，不能用文件编号推断跨源对应。 |
| **10. 事件匹配与全局分配**：候选配对 → 事件组 | A. 加权分数；B. LLM 成对比较；C. 二分类模型/图匹配与全局约束 | **A+C，疑难用 B**。防止同型平台同日多次活动误合并，也防止一篇报道无约束地支持多起互斥事件。 |
| **11. 事件去重与拆分**：事件组 → 唯一事件 ID | A. 按主体、平台、时间、区域规则去重；B. 聚类；C. Agent 复核边界案例 | **A+B**。保留“合并了哪些记录/为什么拆开”；事件 ID 不依赖原文件排序。 |

## 3. 可信判定：只有过关的事实才能进入日报

| 步骤：输入 → 输出 | 可选方案 | 推荐与检查点 |
|---|---|---|
| **12. 逐字段证据表**：事件组 → 字段及证据 | A. 程序逐字段汇总支持/缺失/冲突；B. LLM 从原文中提取并对齐证据片段 | **A+B**。主体、平台、数量、时间、区域、任务分别核验；保存来源类型、文件、行号/片段。 |
| **13. 冲突消解**：证据表 → 字段判定 | A. 显式规则和时空一致性；B. LLM 解释冲突；C. 核验 Agent 调用检索工具补证据 | **A 为准入框架，B 处理难例**。区分“没提到”“说法不同但可兼容”“明确矛盾”；不能简单多数投票。 |
| **14. 事件准入**：字段判定 → 纳入/排除/待审 | A. 三源规则门控；B. 校准概率分数辅助排序；C. 人工审阅低置信度样本 | **A 必须**。三类来源可关联，关键事实至少两类支持，第三类无无法消解的明确冲突；待审不自动进入标准日报。 |
| **15. 海域及进出关系判定**：可信事件 → 东海/南海/黄海/其他 | A. 官方区域词典与经纬度规则；B. LLM 判定含糊句子；C. 地理边界与轨迹穿越计算 | **A 主、B/C 补边界**。通行区域只有明确进入或离开三海时才计入。 |

## 4. 日报内容：分别处理当日与跨日信息

| 步骤：输入 → 输出 | 可选方案 | 推荐与检查点 |
|---|---|---|
| **16. 当日统计**：节点日可信事件 → 数量与分组 | A. 按事件 ID、平台和架/艘次确定性聚合；B. SQL/数据仓库查询 | **A**。先去重再计数，核对总数与方向/国家/机舰分项；只取节点当日。 |
| **17. 跨日主线追踪**：历史可信事件 → 活动链 | A. 同主体/平台 + 时空连续性规则；B. 时序图匹配；C. LLM 辅助解释转移/间歇 | **A+B 可选**。只看赛段起始日至节点日；相隔 ≤7 日通常连续，8—14 日分阶段，≥15 日通常新线索。 |
| **18. 重点主线选择**：节点日外（台）事件与活动链 → 一条主线 | A. 规则排序：节点日存在、≥3 个日期、证据质量和重要性；B. LLM 在合格候选中选择并解释 | **A 筛资格、B 排优先级**。不满足 3 日条件时明确写证据不足，不拼凑。 |
| **19. 正文写作**：事实表、统计、主线 → DOCX 文字 | A. 模板填充；B. LLM 基于事实表写作；C. 写作 Agent 分章节生成 | **A 固定结构、B 写分析**。标题和五节固定；事实与推断分开，每项重要判断引用事件 ID。 |
| **20. 明细表生成**：当日可信事件 → XLSX | A. 程序映射字段；B. 模板填充 | **A**。仅 `飞机`、`舰艇` 两表，列序、单位、数量和日期按官方规范。 |
| **21. 附件图表生成**：当日可信事件 → 4 张 PNG | A. 程序绘图；B. 地图底图/地理绘图；C. LLM 只建议可视化重点 | **A/B**。图题、图例、坐标和单位完整；不能把示意坐标当真实位置。正文要引用全部图表。 |

## 5. 交付闭环：保证内容正确且可复现

| 步骤：输入 → 输出 | 可选方案 | 推荐与检查点 |
|---|---|---|
| **22. 事实回查**：DOCX/XLSX/PNG → 错误清单 | A. 程序逐项回查事实表与统计；B. 独立 LLM/审校 Agent 核对正文 | **A+B**。找无来源数字、时间越界、正文与表格不一致、图表数据不一致。 |
| **23. 格式与文件验收**：文件包 → 通过/失败 | A. 程序打开 DOCX/XLSX/PNG 并检查章节、两表列序、4 图、命名；B. 渲染后人工抽查 | **A 必须，B 抽查**。失败时阻止提交，不用模型决定格式是否合规。 |
| **24. 失败恢复与缓存**：各步状态 → 可续跑任务 | A. 每步保存 JSONL/Parquet，失败只重跑该步；B. 工作流引擎管理重试、超时和依赖 | **A 起步**。模型调用记录输入哈希、版本、温度和错误；重复运行同一输入可复现。 |
| **25. 评测与版本管理**：人工标注和生成结果 → 指标与最佳版本 | A. 固定标注集、自动计算指标；B. A/B 对比不同模型与阈值；C. 主动学习补标疑难样本 | **A+B**。重点看错误归并、字段准确率、事件精确率/召回率、跨日主线、8 节点平均分、成本与时间。 |

## 六、模块之间传什么数据

建议固定五种中间对象；无论用 Workflow、单 Agent 还是多 Agent，都复用这些格式：

1. **原始记录**：来源、日期、文件路径、工作表/行号、原文、哈希。
2. **抽取记录/雷达轨迹**：原始值、标准值、轨迹点、异常标签、原文定位。
3. **候选事件**：候选 ID、关联的三源记录、匹配分数、合并/拆分依据。
4. **可信事件**：事件 ID、逐字段取值、支持/冲突证据、纳入状态、排除理由。
5. **活动链与日报包**：历史事件 ID、阶段、节点日统计，以及 DOCX/XLSX/PNG 的来源映射。

每一步只读取上一阶段的对象，不让报告模型直接翻原始文件自行编造结论。重要字段须能沿“日报 → 可信事件 → 证据片段/雷达行 → 原文件”反查。

## 七、推荐的第一版完整 Workflow

**程序读取和清洗 → 规则/向量混合召回 → 全局事件匹配 → LLM 抽取难字段及解释冲突 → 程序执行三源准入与海域过滤 → 程序统计和追踪 → LLM 写分析 → 程序生成文件 → 独立回查和格式验收。**

先用少量人工标注样本测试步骤 9—14。这些步骤决定事实是否正确，收益通常比增加写作 Agent 更直接。若单个疑难事件核验 Agent 能显著降低错误归并，再接入；若多个专职 Agent 在同一标注集上继续提升准确率，才考虑把 Workflow 的相应节点改成多 Agent 协作。

## 八、当前最该投入什么，哪些先复用

| 优先级 | 工作 | 理由 |
|---|---|---|
| **P0：先做** | 从不同日期抽取“同型平台多活动、跨源冲突、雷达错配、跨日主线”等样本，标注真实事件与字段；建立固定评测脚本 | 没有真值就不知道改动是否提高准确率 |
| **P0：集中攻关** | 改进跨源候选的全局分配与事件归并；把字段支持、明确冲突和异常消解拆开判定 | 错误合并或采信会同时污染明细、统计和正文，信息准确度权重最高 |
| **P1：按需增强** | 给规则无法判定的事件增加 LLM/Agent 复核，输出结构化结论和原文定位 | 只对难例付模型成本，便于同基线对比 |
| **P2：复用改造** | 沿用 Claude 版本的 `lexicon.py`、`extract.py`、`radar.py`、`tracking.py`、`report.py`、`charts.py` 和交付校验；用评测结果决定具体补丁 | 这些模块已有可运行实现，先避免重复建设 |

Claude 版本的 `fusion.py` 已提供匹配和字段核验的起点，但其事件分配采用贪心匹配、字段裁决大量依赖票数与规则；这两处应优先对照标注样本检查。报告排版与图表改进应在核心事实可靠后再投入。
