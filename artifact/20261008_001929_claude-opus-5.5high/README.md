## 运行

```bash
pip install -r requirements.txt
python run.py --input "../../赛题2-初赛/数据" --output output --stage prelim
```

## 方法

| 模块 | 文件 | 要点 |
|---|---|---|
| 领域词典 | `bdci/lexicon.py` | 80 余个海域地名（方向、中心坐标、半径）、国家别名、170 余型平台及合理隶属国、任务词表 |
| 文本抽取 | `bdci/extract.py` | 去除“据××报道”信源短语；最长匹配识别平台（含“X”号/级、简称、代号）；就近抽取国家、数量、起止时间、地点、任务、进入/离开；遮蔽平台名防止“反潜巡逻机”被识别成任务；排除“菲律宾海军”“日本海上自卫队”中的伪海名；通行海峡只有明确进入/离开时才计入三海 |
| 雷达解析 | `bdci/radar.py` | 按批号聚合航迹；识别两处交替出现的点迹（位置漂移/轨迹跳变）并拆成候选解释；识别批内区域错配、主体—平台错配、时间异常；坐标反查地名 |
| 关联核验 | `bdci/fusion.py` | 开源↔雷达、舆论↔事件簇一对一贪心匹配（平台/国家/地点/时间/任务/数量打分），再对互补的不完整簇做合并；字段级投票：**平台、国家、活动方向都必须至少两类来源支持**，第三类冲突按多数结果和异常解释消解并记录；雷达主体—平台错配时雷达国家不计入支持 |
| 主线追踪 | `bdci/tracking.py` | 仅用起始日至节点日的数据；在节点日仍出现的外（台）方三海平台中按出现日期数、方向多样性、主体优先级选主线；≤7 天连续、8—14 天另起阶段、≥15 天视为新线索；合并为 2—3 个阶段，判定持续/转移/间歇/离开 |
| 报告 | `bdci/report.py` `bdci/charts.py` | DOCX 固定标题和六个章节，每句标注【核实】或【研判】并附事件编号与证据文件号；XLSX 严格 16/11 列；4 张 PNG 含图题、图例、坐标和单位，正文引用并嵌入 |

在全部 80 天上：约 4,270 个事件通过核验（其中约 3,970 个是三源齐全），只有 27 条单源线索被排除；被处理掉的典型噪声包括：开源军情把柯林斯级潜艇写成意大利、舆论把 E-767 写成俄军、雷达把福建号标成日本、雷达舰船批内两种活动区域、飞机批号在南海和东海两处交替出现等。

## 已知局限

- 没有官方 XLSX 示例：日期列写成 Excel 日期类型，时间写成 `HH:MM` 文本，有官方样例后应逐列对齐。
- 呼号列只在文本给出括号代号时填写，雷达表本身没有呼号字段。
- 只有两类来源且互相冲突时直接排除；如果评测更偏向召回，可以放宽为“雷达无异常时优先采信雷达”。
- 海岸线是示意用的粗略折线，不是测绘数据。
