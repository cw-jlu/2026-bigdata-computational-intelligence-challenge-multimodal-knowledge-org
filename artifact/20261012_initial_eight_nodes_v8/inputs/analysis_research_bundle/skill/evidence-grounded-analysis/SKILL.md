# 证据型历史资料分析

## 明确任务边界

只处理公开历史研究、演示或脱敏情境。不要重建实时部队位置、生成具体行动预测或提供作战规划。不要调用雷达融合、目标关联或轨迹重建流程。

识别目标截止日、输出章节、输入性质和允许使用的外部资料。输入不足时只问关键缺口；不要编造事实让文稿看起来完整。

读 `references/input_output_contract.md`。遇到本比赛，读 `references/competition_rules.md`；不要把比赛规则套到无关任务。

## 固定事实层

将用户提供的事实台账、模板和原始材料分开。模板不是事实真值；示范报告不能自行标为已核实。保留上游证据定位和待解决冲突，不改动事实、数量、单位、图表或其他章节以迎合某个解释。

只在可追溯的已核实历史摘要上写分析，不负责从作战数据生成该台账。

## 检索并登记外部材料

优先读原始发布方的论文、报告、公开统计和政策原文，再考虑权威二手讨论。需要网页时使用环境中实际可用的浏览工具；没有工具时只用已提供材料，不假称已检索。

按 `references/source_catalog.json` 的字段建立当前任务资料目录。该目录只是起点，逐条核查时效和相关性，不要全部加载进每份报告。根据需要读 `references/external_data_cards.json`；这些卡片是有限摘录，不是完整原始数据库。

记录公开日或可靠上界、内容时期、版本、URL、段落/页码、发布者、独立来源组和可支持的具体论点。正文没有打开就标记未读。当前数据库中的早年记录仍可能经过后期修订，不能仅按数据年份排除穿越。区分英文版、中文版和原版的上线时间。

禁止将转载数量当成独立证据；禁止把模型记忆伪装为外部来源。把正文中的方法引用与实证/背景引用分开统计。

## 运行来源审计

需要代码运行时执行：

```bash
python scripts/audit_sources.py --catalog references/source_catalog.json --as-of 2025-05-10 --used E01 D01 --substantive E01 D01 --output audit.json
```

替换路径、日期和真正使用的来源ID。审计返回FAIL时先解决问题，不能隐藏错误。脚本只核对日期、版本元数据及引用资格；PASS不证明真实性、语义支持、上游事件核验通过或获得比赛高分。

## 先形成论证，再写正文

为每个结论准备简短证据卡：问题；可观察事实；外部依据；比較口径；结论；至少一种合理替代解释；缺少的证据。不要输出冗长私人推理，只输出可复核的论证摘要。

检查外部材料是否真正增加背景、比较基线、合理替代解释或对结论的约束。仅装饰性提及的引用删除。不要由年度军费推出某日行为；不要由一般装备用途推出实际任务；不要把数据覆盖变化解释为真实活动变化。

只迁移专家案例的组织方式。将政策立场和专家观点明确归属于其发布方，不机械迁移作者结论。读 `references/writing_template.md`。较完整的调用提示词见 `references/generation_prompt.md`。

## 生成并终检

以用户模板为准输出正文。针对本比赛，仅写第二节，保持“总体判断 + 2—3阶段”的框架；没有3个真实证据日期时指出无法满足，不凑日期。

逐段区分已核实事实、外部背景、机构观点与推断。判断强度不得高于证据强度；明确不确定性来源，不随意生成百分比置信度。

另出 `audit.json`，列出采用/排除来源、每项主要结论的引用和限制。审计数据不得混入官方只允许固定字段的提交表。需要DOCX时调用当前环境的文档能力并检查渲染；缺少渲染能力时不要声称版式已检查。

保存所用资料版本、提示词、模型参数和输出哈希，以便复现。不得宣称已完成未执行的节点实验或评分。后续需比较方案时，固定事实台账、模型、预算和节点再做对照。
