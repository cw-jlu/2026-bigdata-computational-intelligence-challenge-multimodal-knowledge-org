## 本轮对后续改进最有价值的结论

1. **要同时减少误纳和漏项，必须分别检查它们。** 只回查已纳入的205条，无法找到候选生成阶段就漏掉的事件。原文到候选、候选到三源、三源到逐字段支持应分别留证；这里的工程诊断指标不是平台完整性或准确性分数。
2. **事件关联与字段裁决要分开。** 三篇材料属于同一事件，不代表数量、任务和区域每个字段均得到支持。弱关联造成的错误，会继续污染跨日统计与分析。
3. **谨慎不等于只写“不能证明”。** 要说明现有证据究竟支持哪个有限判断，哪些解释仍不能区分。不得用免责声明代替判断，也不能为了增加解释性编造动因。
4. **外部材料必须改变论证。** R07 的具体贡献是限制“P-8A只对应反潜”的理解；它不证明2025年比赛里的飞行参与了该历史安排。R06写的是计划，不能改写为演习均已实施。

## 时间与证据边界

- 节点为2025-05-10、05-18、05-30、06-09、06-17、06-29、07-09、07-17；赛题内事件仍只用2025-05-01至各节点的原始三源。
- 有年代明确的固定原文与“当前网页标着旧日期”分别登记。R04、R05、R09没有独立历史快照，不直接作为正式日报的节点前外部实证；R04、R05仅用于方法设计。R01、R02、R03本身也是方法资料，不计作实证引用。
- 外部资料不能充当缺失的比赛第三源，不能消解赛题内关键冲突，不将现实世界事件强行映射到派生数据集，也不能用一般性能否定或补造当次任务。
- 资格审计只检查日期、文件与登记信息；程序 PASS 不是内容正确、因果解释成立或平台提分的证明。

## 文件与复查

- `originals/`：6份原文；`extracted/`：可搜索文本。HTML提取保留导航等文本，PDF提取可能有OCR、断词和表格顺序问题，引用以原文为准。
- `provenance/`：发布记录和授权说明网页；`retrieval_log.json`：成功与失败的实际下载记录。
- `reading_log.json`、`qa/`：已读范围与关键页图像；只宣称检查列出的页面，不宣称通读整本45页方法手册。
- `source_catalog.json`、`node_eligibility.json`：来源与用途资格；`review_schema.json`：后续事实复核应记录的字段，不是自动裁决器。
- `manifest.json`：归档文件哈希；`validation.json`：离线核对结果。运行 `python verify_bundle.py` 复查。
- `fetch_sources.py --output <新空目录>`：重新下载并提取，需 Python 3、`pypdf`；网络失败和网页改版均可能使新结果不同。本轮原件不覆盖。
