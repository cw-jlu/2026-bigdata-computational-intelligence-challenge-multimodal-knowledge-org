# 系统处理流程与算法要求

## 1. 推荐流水线

```text
原始文件读取
  -> 文本/XLSX 解析
  -> 字段清洗与标准化
  -> 实体抽取与别名归一化
  -> 跨源事件候选生成
  -> 事件聚类与冲突检测
  -> 三源证据核验
  -> 海域过滤与节点统计
  -> 跨日主线追踪
  -> DOCX/XLSX/PNG 生成
```

## 2. 标准化对象

至少应统一日期、国家或地区、飞机和舰船名称、平台型号、批号、数量、时间、任务、活动方向、具体活动区域，以及进入、活动、离开关系。应处理简称、全称、别名和不同表述。

## 3. 事件关联特征

可综合使用主体、平台、批号、时间窗口、活动区域、任务、基地或港口、雷达轨迹、来源文本相似度和时空连续性。关联时既要合并同一事件的多源证据，也要避免将同型平台同日不同活动错误合并。

## 4. 可信度与冲突处理

建议为每个事实保存来源、证据片段、支持/冲突状态和最终判定。冲突应至少记录冲突字段、冲突来源、处理依据和是否排除。不得直接采用单一文本来源或明显异常雷达记录作为最终事实。

## 5. 节点日报规则

- 除第二节外，日报章节、统计表和附件只反映节点当日信息。
- 第二节从节点当日仍出现的外方或台湾三海活动中选择一条重点主线。
- 重点主线至少覆盖 3 个不同日期，并回溯赛段起始日至节点当日的证据。
- 应概括为 2—3 个阶段，采用“总体判断 + 分阶段变化”表达持续、转移、间歇或离开。
- 相邻证据日期相差不超过 7 日通常视为连续；8—14 日可归入同一主线但需区分阶段；相差 15 日及以上通常视为新线索。

## 6. 可复核性要求

中间结果应保留原始文件标识、记录定位、解析结果、实体映射、事件 ID、证据关系和过滤原因，方便从最终日报反查到原始材料。
