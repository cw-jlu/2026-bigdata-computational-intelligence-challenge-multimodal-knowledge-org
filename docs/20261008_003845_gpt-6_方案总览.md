# 赛题方案地图：三种架构 × 各模块选型

本题输入是开源军情 TXT、网上舆论 TXT 和雷达 XLSX；输出是 8 个节点的 DOCX、XLSX、PNG 日报。先选系统由谁调度，再给每个模块选具体做法。这两层可以自由组合。

## 一、系统架构只考虑三种

| 架构 | 如何运转 | 适合的情况 | 主要代价 |
|---|---|---|---|
| **Workflow** | 程序按固定顺序调用各模块，模型只完成指定步骤 | 追求稳定、速度、复现和格式合规 | 疑难事件需要专门设计分支 |
| **单 Agent** | 一个模型决定何时检索、核验、重试与生成，工具完成读写 | 规则难覆盖、流程经常需要临场调整 | 调用多、结果波动大，必须限制步骤与权限 |
| **多 Agent** | 抽取、关联、核验、分析、审校由不同 Agent 分工，协调器汇总 | 各环节确有不同专长，且复核能提高准确率 | 成本、延迟、协调和错误传播更高 |

**我的建议：先以 Workflow 调度，给疑难事件接入一个受约束的核验 Agent；只有评测证实分工有效，再升级为多 Agent。** 不管采用哪一种架构，时间边界、三源准入和交付格式均由程序强制检查。

## 二、各模块有哪些可选做法

以下是模块菜单，不要求每个模块都使用模型。表中「推荐起步」是第一版值得尝试的组合，可根据标注集结果替换。

| 模块 | 方案 A：简单稳定 | 方案 B：模型增强 | 方案 C：更复杂的做法 | 推荐起步 |
|---|---|---|---|---|
| **1. 原始数据读取** | 正则解析 TXT，`pandas/openpyxl` 读取 XLSX | LLM 处理解析失败或格式异常的文本 | Agent 自行选解析器并修复异常文件 | A；失败样本走 B |
| **2. 文本要素抽取** | 正则、词典抽取国家、平台、区域、任务、时间、数量 | LLM 按 JSON Schema 逐篇抽取并引用原文 | 微调专用信息抽取模型；复杂篇章用 Agent 追问 | A+B 并行对照 |
| **3. 实体与别名统一** | 维护平台、国家、区域别名表 | 用向量相似度或 LLM 判断是否同一实体（不考虑时间和成本LLM是最优解） | 建实体知识图谱，关联型号、所属国和舰名 | A；歧义交给 B |
| **4. 雷达轨迹整理** | 按批号聚合点位，检查时间、速度、经纬度和数量 | 模型解释疑似异常或与文本不一致的轨迹 | 轨迹聚类/时序异常检测模型 | A；异常先隔离 |
| **5. 跨源候选召回** | 用日期、平台、国家、海域做条件筛选 | 用向量检索找不同措辞的同一事件 | 混合检索：条件筛选 + 向量 + 重排序 | A+B，取候选并集 |
| **6. 判断是否同一事件** | 加权比较主体、平台、时间、区域、任务；做一对一/一对多约束 | LLM 成对比较证据并给出理由 | 二分类匹配模型、图聚类或全局最优匹配 | A 生成候选，B 复核边界样本 |
| **7. 事实冲突与可信度** | 对每个字段记录支持、反对和缺失；规则决定纳入/排除 | LLM 逐字段对照原文，解释冲突能否消解 | 专职核验 Agent 搜索证据、复核雷达和回退错误归并 | A 为最终门槛，B 处理疑难 |
| **8. 海域与节点统计** | 区域词典、坐标范围、时间过滤；按去重事件计数 | LLM 只处理含糊的进出海域表述 | 地理知识库 + 轨迹穿越海域边界判定 | A；边界情况 B |
| **9. 跨日主线追踪** | 同主体/平台关联，检查时间间隔、海域和任务变化 | LLM 总结“持续、转移、间歇、离开”及 2—3 阶段 | 时序事件图或 Agent 反复检索历史证据 | A 建链，B 写分析 |
| **10. 日报正文生成** | 模板填充可信事实、统计和固定章节 | LLM 根据事实表写短段落，要求逐句引用事件 ID | 写作 Agent 起草 + 审校 Agent 核对每一句 | B 写作，A 限制可用事实 |
| **11. 表格与图表生成** | `python-docx/openpyxl/matplotlib` 生成规定文件 | LLM 仅建议关注哪些事实或如何排版 | Agent 调用绘图工具并反复调整 | A；数值来自可信事实表 |
| **12. 最终审校** | 程序检查文件、字段、时间边界、三源证据链和空值 | LLM 查正文是否误述、遗漏重点或引用错事件 | 独立审校 Agent 与生成 Agent 交叉复核 | A 必须，B 可加 |

### 两个最关键的模块怎么选

- **事件关联（5—6）**：先高召回地找候选，再严格判定是否同一事件。同型平台同一天可能有多次活动，不能仅凭平台名或文件序号合并；同一篇报道也不能无约束地支持多起互斥事件。
- **可信度（7）**：以“字段”为单位核验主体、平台、数量、时间、区域、任务。关键事实至少获两类来源支持，第三类来源不能存在无法消解的明确冲突；雷达异常不自动压过文本。

## 三、三种可直接实现的组合

| 组合 | 模块分配 | 什么时候选 |
|---|---|---|
| **W1：全 Workflow** | 规则读取与清洗 → 检索/匹配 → 固定 LLM 抽取与冲突核验 → 规则准入 → LLM 写分析 → 程序生成和校验文件 | 默认首选；容易定位错误 |
| **A1：单 Agent + 硬约束工具** | Agent 调用读取、检索、候选比较、证据查看工具；程序独立执行准入和格式校验 | 疑难事件多，固定分支难写时 |
| **M1：多 Agent + 协调器** | 抽取 Agent → 关联 Agent → 核验 Agent → 分析 Agent；审校 Agent 复核，协调器管理状态与重试；程序执行硬约束 | 标注集显示各环节分工能稳定提高分数时 |

**推荐路线：W1 → W1 加疑难事件 Agent → 视评测结果决定 A1 或 M1。** 单 Agent 与多 Agent 都可以复用同一套模块输入输出和证据结构，避免换架构时重写系统。

## 四、如何决定哪个方案真的更好

先人工标注少量节点样本，包含正常事件、同型平台多次活动、文本冲突、雷达异常、跨日主线。所有方案用同一批样本比较：

1. 事件精确率、召回率、错误归并率。
2. 主体、平台、数量、时间、区域、任务的逐字段准确率；冲突检出率。
3. 跨日主线是否覆盖至少 3 个日期，阶段和节点时间边界是否正确。
4. 8 个节点的平均日报质量、运行时间、模型费用、失败重试次数。

如果增加 Agent 只让文字更漂亮，却增加错误归并或证据缺失，就保留更简单的 Workflow。最后交付的每条结论都应能追溯到原始文件、雷达行号、文本片段和判定理由。
