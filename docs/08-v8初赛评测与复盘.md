## 2. 分析薄弱有可核查的实现依据

本轮第二节实际由确定性模板生成，见`code/build.py`的`POINTS`、`EXTERNAL`和`analysis()`，没有另行调用分析增强模型。八节点拥有各自事实和结论，但大部分段落共享“区域/任务有变化”“科目转换、合作训练或同型平台轮换”“身份不足不能作更强判断”的句式。限制写得谨慎，仍没有充分回答：哪些变化最重要、为什么这个变化比另一条主线更值得分析、哪个历史基线能区分解释、现有证据具体排除了什么。

`code/select_lines.py`按日期在`SELECT`中编码指定主体/平台，节点候选确有比较数据，但通用`selection_reason`对所有节点相同，缺少逐候选选择和弃选的具体论证；两个节点的原始自动分阶段判定为不适合，配置又通过合并阶段并置`suitable=True`处理。这并不证明分组错误，但“编码可复现”不能替代节点相关性和阶段充分性的判断。

八节点共22个阶段，12个仅有一个证据日期。6月9日莱库号3次活动被划为3个单日段；7月9日主线最后两段也各只有一天。报告正确地没有把单日写成持续状态，但三个证据日期达标不等于形成了值得展开的演变主线。用长篇共同限制包裹稀疏变化，容易保留分析外形而缺少分析内容。应先判断证据能支持哪些变化，不以凑齐2—3阶段作为目标。

5月30日和6月29日没有采用合格新增外部实证材料；其他节点所用资料大多为2024德国部署/合作训练、2022加拿大政策或不同平台/区域演习背景，主要只能证明某种替代解释有可能，不能建立本节点强度、频率、任务集中或方向转换的可比基线。这些引用有历史资格且未冒充比赛真值，但相关性和区分解释能力较弱。分析低分不应简单归因于“引用不够多”。

每个分析推断的审计前提往往指向全部H记录，而非该阶段最直接的观察与对照。`validate.py`检查前提ID存在，不能证明这些前提实际支持具体因果/阶段判断。下一轮应把每个结论细化为观察、对照、解释、限制和最直接的前提ID，删除重复的限制段落。

## 3. 事实核验仍有结构性弱点

`code/events.py:text_atoms()`已经从正文提取并分部分活动段，不是按标题或文件序号判断，但每个段的区域取最长命中、任务按词典命中、时间取首尾；同段多平台会继承同一组任务、区域和时间。主体与平台对应依赖邻近国别提及。它仍缺少充分的语法关系、否定/引用/条件范围、共同活动数量与每个平台数量的区分。抽取结果一旦共享同一种偏差，两类来源一致也不自动等于真实支持。这里只指出代码能力缺口，没有将其当成某条已确认错报。

`position_support()`将雷达完整批次读入后，区域相容判定主要使用坐标中位点及210/340公里半径，泛海域使用矩形包络；读了全部行并检查跳变，仍不等于验证了轨迹与具体活动区域/任务的时间关系。中位点可掩盖空间分支或部分时段冲突，宽半径只说明粗略相容，不能当作细地名支持。不能用“全部点必须在同一区域”的新僵硬规则替代它；应按事件时段和可分辨轨迹分支查证进入、活动或离开关系。

关联先采用全局一对一匹配，无法区分同型同日多活动时只对近似同分且缺少时间的情况保留歧义。更高匹配分仍可能来自已误抽取的任务/区域；资源竞争、关联反事实和不同粒度报道尚未形成独立校准。未选竞争证据只在具体地名或显式时间能唯一锚定时进入冲突闸门，其他遗漏关联不能据此视为无冲突。下一轮应保存多种关联假设及其各自支持/反证，再核对身份、范围和数量归属，而非放宽双源原则。

205条当日纳入记录中，86条输出区域只到东海/黄海/南海层级。这是本轮对辅助/细地名缺证的谨慎处理，本身不等于错误；但核心字段精度损失可能影响完整性或准确性，具体影响需扣分明细或逐字段独立样本验证。不能为评分补造细区域、基地、起降或任务，也不能用未知绕过明确冲突。

## 4. 现有验证不足以证明质量已经收敛

`validate.py`多数检查是同一冻结台账到正文、表格、图表的一致性，`reproduce.py`证明相同输入能生成相同内容；它们能发现结构或生成错误，不能发现台账内部稳定复现的错误。原始重读抽查每节点仅2纳入、2排除，共32例，且由同一生成者审阅，是有限开发检查，不是独立盲测。此前将“审计齐全、全部PASS”作为较强质量保障，证据不足；这次实测表明流程完成与评分质量需要分开衡量。

正式48文件、96页完整渲染和全八节点复现的工作仍有价值，格式96.5230支持整体版式已较好。剩余3.4770格式分没有逐节点细项，不能确定是长URL换行、表格空白、图布局或ZIP外层所致；目录层级冲突也不能当成已证实扣分原因。

## 5. 下一轮应检验的改进顺序

1. 保留本版代码、评测前48文件、ZIP哈希与本次反馈，取得逐节点/逐字段扣分后再定位。没有细项时，另建覆盖全部节点的分层原始核验集：纳入/排除、同型多活动、跨来源竞争、多平台、否定或引用、噪点与持续冲突分别取例；核验依据先于修复实现，留出未参与调参的样本。
2. 优先检查错误关联、国别—平台—任务关系、数量归属、具体区域和轨迹时段。以独立证据修正误纳/漏纳/字段精度，继续允许真正未知，不按固定比例减条，也不把完整性指标当召回率。
3. 冻结改正后的事实层，再单独比较分析改写：节点候选要有具体取舍；宁可选择证据更充分的主线，也不强凑阶段；统计用同地域、同单位、可解释观测覆盖的基线；外部来源必须直接帮助区分解释。
4. 保留当前格式流水线，主要修改分析深度；准确性、分析和版式改变分别记录。待新的实际平台结果后比较，不预报得分，不把全部增量归因于提示词或模型。

本轮只归档评分、复盘和原评测版本到GitHub，没有将上述计划偷偷实施到本次提交结果。
