# 参赛思考记录

## 1. 关于之前的 KDD Data Agent 比赛

这里的 KDD 指之前参加的 KDD 比赛，核心方向是 Data Agent，不是知识发现（Knowledge Discovery）的泛称。

当前想法：之前 KDD 比赛中使用的可能是能力有限的模型，因此当时采用的 Data Agent 策略不一定能直接迁移到本赛题，也不一定在本赛题中稳定生效。

需要进一步验证：

- 之前的 Data Agent 流程与本赛题的多源事件重建任务是否匹配；
- 弱模型经过规则、检索、工具调用和多阶段流程增强后，能否完成可信事实核验；
- 模型能力不足时，错误主要来自抽取、事件关联，还是事实核验和报告生成。

## 2. 对本赛题的整体理解

本赛题不只是文本分类或信息抽取，而是一套完整的：

> 多源数据清洗 + 实体与事件关联 + 可信事实判定 + 跨日态势分析 + 结构化日报生成工具。

其中“可信”是核心。系统不能简单采用某个来源，也不能只按多数表决，而要结合至少两类来源支持、第三类来源冲突情况、时空连续性和领域约束。

## 3. 关于强模型的优势

使用更强的模型可能在文本理解、实体归一化、事件关联和趋势总结方面形成明显优势，尤其适合处理复杂表述和跨文档线索。

但强模型不等于自动获胜，原因包括：

- 输入数据仍需要可靠清洗和切分；
- 模型可能产生幻觉或错误合并事件；
- 时间边界和海域规则必须由程序严格控制；
- DOCX、XLSX、PNG 的格式输出需要确定性校验；
- 评测不仅看表达，还重点看事实准确度和证据关系；
- 外部模型/API 的版本、调用限制和随机性会影响复现。

因此，更合理的判断是：强模型可以显著降低自然语言理解难度，但真正的竞争力仍来自“强模型 + 规则约束 + 多源证据链 + 自动化输出 + 可复现工程”。

## 4. 待验证问题

- 是否允许稳定调用外部大模型，还是应准备本地模型方案；
- Agent 在事件关联和冲突消解上的收益是否高于普通流水线；
- 评测更偏重结构化事实匹配，还是也会评价自然语言表达质量；
- 如何设计中间事实表，使最终日报能够反向追溯到原始证据。
